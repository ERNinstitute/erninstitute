ERN Meta-Analysis Studio · Version 1.0

Methods, validation and citation

The Studio prepares effect sizes, fits classical inverse-variance meta-analysis models and exports transparent results. This page describes the supported calculations, the tests performed, and the limits researchers should consider before reporting an analysis.

Open the Studio

How to cite the Studio

For methods sections or software lists, cite the version used and the access date when relevant. The recommended APA-style software reference is:

ERN Institute. (2026). ERN Meta-Analysis Studio (Version 1.0) [Computer software]. https://erninstitute.com/tools/meta-analysis-studio/

The Studio is independent software. Its citation does not replace citations to the underlying meta-analysis methods or original dataset sources.

Current statistical workflow

  • Effect sizes: Hedges g from eligible independent-group means, Student t, or two-group F tests; Fisher z from correlations; log odds ratios from binary event counts; and generic inverse-variance inputs.
  • Models: common-effect inverse-variance pooling and random-effects pooling. Between-study variance can be estimated using restricted maximum likelihood (REML), Paule–Mandel, or DerSimonian–Laird.
  • Inference: Wald or Knapp–Hartung confidence intervals, with the automated selection rule documented in the Studio. The inference setting is exported with the fitted model.
  • Heterogeneity: Cochran's Q, between-study variance (τ²), and estimator-consistent I² and H² for random-effects models. Prediction intervals are available when the selected model supports them.
  • Reproducibility: exported files retain the submitted rows, effect-size calculations, validation notices, model settings, results, and plots.

REML and Knapp–Hartung are established methods, also implemented in the R metafor package (Viechtbauer, 2010). We do not imply that identical output is guaranteed across packages when defaults, small-sample corrections, variance conventions or prediction-interval formulas differ.

Validation status

6curated real datasets parsed and modeled
7metric-specific models in repository smoke tests
28pooled-model numerical comparisons

On November 4, 2026, the existing JavaScript unit tests and a repository-data regression suite passed. A separate Python/NumPy/SciPy implementation recalculated 28 common- and random-effects models from the same extracted effect estimates and sampling variances. The comparisons covered pooled estimates, standard errors, confidence intervals, Q, I², REML, Paule–Mandel, DerSimonian–Laird, inference selection, and eligible prediction intervals. The largest absolute numerical discrepancy was below 0.000001.

We also compared a worked REML example from the published metadat/metafor documentation with the Studio's result from the corresponding 12-effect brain-image dataset. The pooled raw mean difference (0.07), standard error (0.03), 95% confidence limits (approximately 0.00 to 0.14), and Q (15.73) agreed at the precision printed in the reference. That comparison uses published R output, rather than a fresh execution of R.

What this establishes: the pooling calculations agree closely with an independent numerical implementation on the tested cases and with one published metafor worked example. What it does not establish: complete validation of every raw-data conversion, every possible input or output file, or direct agreement across a comprehensive R/metafor test battery. A separate R interoperability audit remains to be completed.

The tests are available in the public website source repository. Run the JavaScript suites with node tests/meta-analysis-engine.test.js, node tests/effect-size-converter.test.js, node tests/repository-datasets.test.js and node tests/metafor-published-example.test.js. The SciPy comparison can be reproduced with python tests/statistical-crosscheck.py when NumPy and SciPy are installed.

Important design limits

The Studio assumes that the pooled estimates can legitimately be treated as independent. Repeated study labels trigger a review step, but confirming independence does not correct dependent effects. The current models do not estimate multilevel structures, cluster-robust variance, paired-outcome covariance or other dependency structures.

The raw-data converter is intentionally restricted to clearly defined designs. For adjusted, paired, repeated-measures, cluster-randomized or otherwise complex designs, calculate an appropriate estimate and sampling variance using a design-aware method before considering generic inverse-variance pooling. Ineligible statistics should not be forced into the supported conversion routes.

Different effect-size metrics are fitted separately. A mixed dataset does not cause the Studio to combine Hedges g, Fisher z, and log odds ratios into one pooled estimate.
